代理问题看似五花八门，按现象分类后可以用固定的顺序排查。本文介绍排查框架，具体场景的详细步骤将逐步补充。

## 现象一：连接失败

优先检查三件事：代理类型与参数是否匹配、账号密码是否有效、端口是否可达。多数连接失败源于这三点。

## 现象二：泄漏（真实 IP 暴露）

通过检测站点确认出口 IP。若出现真实 IP，重点检查 WebRTC 是否泄漏真实地址、DNS 是否走了本地解析、代理是否真的生效。

## 现象三：地区不匹配

出口 IP 的地区由代理决定，而时区与语言由浏览器决定。两者不一致时，需让浏览器的时区、语言与代理出口地区对齐，否则平台会判定异常。

## 排查顺序建议

1. 确认代理协议与参数填写正确。
2. 确认环境已开启代理且出口 IP 为代理 IP。
3. 检测 WebRTC 与 DNS 泄漏。
4. 检查时区、语言与经纬度是否与代理地区一致。

系统性的排查可以大幅缩短定位时间。涉及基础原理的部分可参考[IP 基础](../basics/)，配置相关见[EasyBR 配置](../easybr/)。
