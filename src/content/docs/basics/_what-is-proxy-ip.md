## 一句话结论

代理 IP 是代替你的真实 IP 访问目标网站的"中间人"，网站看到的是代理的地址和特征，而不是你的。

## 代理 IP 的工作原理

不通过代理时，你的请求包从本机出发，途经运营商网络，直接到达目标服务器：

```text
你的设备（真实 IP）─→ 目标网站（看到你的真实 IP）
```

使用代理之后：

```text
你的设备 ─→ 代理服务器（真实 IP）─→ 目标网站（看到代理服务器 IP）
```

目标网站无从判断请求来自哪个真实设备，只能看到代理出口。这是指纹浏览器 + 代理配合的核心逻辑。

## 常见代理类型

| 类型 | 来源 | 特点 | 典型用途 |
|---|---|---|---|
| 住宅代理 (Residential) | ISP 分配给家庭用户 | 真实度高、成本高、速度一般 | 账号注册、多开、广告验证 |
| 静态住宅代理 | 住宅 IP 固定不变 | 长期稳定、伪装度高 | 长期运营账号（Facebook / TikTok / 电商） |
| 数据中心代理 (Datacenter) | 机房 | 速度快、价格低、伪装度低 | 数据采集、低价位需求 |
| 移动代理 (Mobile) | 4G / 5G 运营商 | 运营商级 IP，防封强 | 移动端抓号、放行验证 |

类型对比详见 [住宅 IP 与数据中心 IP 的区别](../../proxy-types/datacenter-vs-residential/)。

## 用"代理 IP"做什么

- 跨境电商多店铺运营，防止关联封店
- 社交媒体多账号，隔离登录
- 广告投放验证，按地区查看广告版面
- 数据采集，更换出口 IP 绕开频率限制
- Web3 空投 / 撸钱等需要多身份的参与者

## 为什么代理常常与指纹浏览器配合

代理只解决"IP 不同"这一层，浏览器指纹（Canvas、WebGL、时区、语言、User-Agent）仍然是同一套，网站仍可通过指纹关联合并。指纹浏览器给每个环境独立的指纹，与代理绑定后，每个环境在网站看来都是一台独立的真实设备。这就是 [代理 IP 与指纹浏览器为什么要配合使用](../../comparisons/proxy-with-fingerprint-browser/)。
